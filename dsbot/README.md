# AFKFlow Discord Bot

Простой Discord-бот на JavaScript с отдельным файлом для каждой команды.

Команда `.help` — собственная справка AFKFlow на Components V2. Она показывает пользователю только те команды, к которым у него есть доступ.

## Запуск

1. Создайте приложение и бота в [Discord Developer Portal](https://discord.com/developers/applications).
2. Если токен уже публиковался где-либо, в разделе **Bot** нажмите **Reset Token** и используйте только новый токен.
3. В разделе **Bot** включите **Message Content Intent**, затем сохраните изменения.
4. Скопируйте `.env.example` в `.env` и укажите токен бота:

```env
DISCORD_TOKEN=ваш_токен_бота
PREFIX=.
GUILD_ID=идентификатор_сервера
TEAMLEAD_ROLE_ID=1545360250838712402
ADMIN_ROLE_ID=1545360252088623125
```

5. Запустите бота:

```bash
npm.cmd start
```

После запуска команда `.wlc` отправляет приветственный embed AFKFlow.

## Идеи и тикеты

Команда `.ide` доступна только роли тимлида и отправляет постоянную панель Components V2 с кнопкой **Предложить** внутри Section-контейнера. После отправки формы бот создаёт приватный канал `idea-username` в категории `1545360278198161409`. Точки и другие недопустимые символы в имени пользователя заменяются на дефисы.

В тикете видят только автора предложения, роль тимлидов и бот. Кнопка **Закрыть** доступна тимлиду и открывает форму итогов, после которой появляется выбор статуса: **Отклонено**, **Рассмотрено** или **Требует немедленной реализации**. Кнопка **Принудительно закрыть** доступна автору тикета.

При закрытии канал удаляется, а полная переписка отправляется transcript-файлом в канал `1545360395902910474`. Кнопка панели продолжает работать после перезапуска, потому что обработчики используют постоянные `customId`.

Команда `.supp` создаёт такую же постоянную Components V2-панель для службы поддержки. Она создаёт приватные каналы `help-username` в категории `1545360282694590567`, сохраняет доступ автора и тимлидов, отправляет итоги автору в личные сообщения и пишет transcript в тот же лог-канал. Лимиты раздельные: `.ide` — 1 тикет в сутки, `.supp` — 3 обращения в сутки.

Команда `/beta` доступна тимлидам (`1545360250838712402`) и бета-тестировщикам (`1545360253519142942`). Она отправляет отчёты Components V2 в канал `1545398951417749674`. Поля: продукт, версия, устройство, суть, шаги воспроизведения, ожидаемый результат, фактический результат и дополнительные детали.

Каждый новый отчёт получает ID формата `ABC-123-XYZ-789` и сохраняется в `data/beta-reports.json`. Тимлид может найти его командой `/betasearch id`. В каждом отчёте есть постоянная кнопка **Дать ответ**: тимлид вводит ответ, после чего он отправляется тестеру в ЛС и в лог-канал `1545360400072179783`.

Чтобы `/beta` не отображалась у остальных участников, откройте **Настройки сервера → Интеграции → AfkFlow → Команды**, отключите доступ для `@everyone` и включите команду для обеих ролей. Даже без этой настройки бот отклонит вызов пользователя без нужной роли.

Для работы тикетов боту нужны права **Manage Channels**, **View Channel**, **Send Messages**, **Read Message History** и **Attach Files**.

## Модерация

Административная роль задаётся через `ADMIN_ROLE_ID` и по умолчанию имеет ID `1545360252088623125`. Тимлид задаётся через `TEAMLEAD_ROLE_ID` и по умолчанию имеет ID `1545360250838712402`.

Доступные команды администратора: `/ban user reason time`, `/kick user reason`, `/timeout user duration reason`, `/warn user reason`, `/unwarn user reason`, `/warnings user`, `/clear amount`, `/lock reason` и `/unlock`.

Время бана указывается как `10m`, `2h`, `7d` или `0` для перманентного бана. Таймаут принимает значения от `1s` до `28d`. Варн хранится 7 дней; третий активный варн автоматически выдаёт таймаут на 24 часа.

Только тимлид может использовать `/slowmode seconds`, `/maintenance on|off` и `/restartbot`. `/maintenance` публикует сообщение о технических работах в новостной канал.

## Slash-команды новостей

Команды `/gnews` и `/gnewstest` регистрируются только на сервере из `GUILD_ID`. Если `GUILD_ID` не указан, бот использует первый сервер, на котором он присутствует. Во время выполнения команды дополнительно проверяется роль из `TEAMLEAD_ROLE_ID`.

Чтобы команды не отображались у остальных участников, один раз настройте права в Discord: **Настройки сервера → Интеграции → AfkFlow → Команды**. Для `/gnews` и `/gnewstest` отключите доступ для `@everyone` и включите его для роли тимлида. Discord не разрешает bot-токену менять эти command permissions через API.

Для настройки команд через интерфейс Discord нужны права владельца сервера или **Manage Server**. Самому боту для публикации нужен **Mention @everyone**.

`/gnews` сразу публикует обновление в новостном канале `1545360330383687760`.

`/gnewstest` отправляет предпросмотр в канал `1545360385727799376`. Кнопка **Опубликовать** сохраняется в файле данных и продолжает работать после перезапуска бота.

Параметры обеих команд: `topic`, `title`, `text`, а также необязательные `color`, `image` и `footer`.

Номер первой публикации — `assembly v.0.0.0`. Все публикации записываются в `data/news.log`, а черновики и следующий номер сохраняются в `data/news-state.json`.

## Новые команды

Каждая команда хранится отдельным JavaScript-файлом в папке `commands/`. Для добавления команды создайте файл с экспортами `name` и `execute(message, args)`.
